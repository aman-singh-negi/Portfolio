# AMAN NEGI — PERSONAL PORTFOLIO

## Master Build Specification for Devin AI

**Document type:** Product + Design + Engineering specification
**Project:** Personal engineering portfolio
**Primary goal:** Build a premium, professional portfolio for a 4th-year B.Tech Computer Science student targeting software engineering/product engineering roles.

---

# 1. PRODUCT VISION

Build a portfolio that feels like a **real, carefully engineered software product**, not a conventional student resume website.

The visual direction is:

* **70% Apple-like**
* **20% modern developer/product tooling**
* **10% Mission Control**

The site must communicate:

> **Professional engineering ability, technical depth, curiosity, and product-building mindset.**

The design should be:

* Minimal
* Premium
* Engineering-focused
* Highly readable
* Spacious
* Fast
* Responsive
* Subtle rather than flashy
* Interaction-rich without being gimmicky

The Mission Control concept should be **subtle**.

Do NOT turn the site into a sci-fi dashboard or gaming interface.

---

# 2. PRIMARY USER

The primary visitor is a:

* Recruiter
* Hiring manager
* Software engineer
* Technical interviewer
* Potential collaborator

The visitor should understand within approximately 30 seconds:

1. Who Aman is
2. What he focuses on
3. What he has built
4. What technologies he uses
5. Evidence of his engineering activity
6. His achievements/certifications
7. How to view his resume
8. How to contact him

---

# 3. DESIGN PRINCIPLES

## 3.1 Apple-inspired visual language

Use:

* Large typography
* Generous whitespace
* Clean grids
* Restrained colors
* Minimal borders
* Subtle shadows
* Smooth transitions
* High-quality project imagery
* Strong visual hierarchy

Avoid:

* Excessive gradients
* Neon colors
* Glowing cards
* Excessive glassmorphism
* Huge 3D objects
* Excessive parallax
* Skill percentage bars
* Generic developer-template aesthetics

---

# 4. COLOR SYSTEM

Primary theme: **Pure Light**

Suggested initial palette:

```text
Background:       #FAFAFA
Surface:          #FFFFFF
Primary text:     #111111
Secondary text:   #666666
Muted text:       #999999
Border:           #EAEAEA
Hover border:     #DADADA
```

Use **one restrained accent color**.

Start by exploring a professional blue/indigo accent.

Do not use many accent colors.

The status indicator may use a restrained success green independently.

All colors must maintain strong accessibility contrast.

---

# 5. TYPOGRAPHY

Use a modern professional sans-serif.

Preferred candidates:

* Geist
* Inter
* SF Pro-like system stack

Optional monospace:

* Geist Mono
* JetBrains Mono

Use monospace only for:

* Technical metadata
* Status labels
* Dates
* Keyboard shortcuts
* Developer statistics
* Command palette metadata

Do not use monospace for large paragraphs.

Typography should be one of the primary visual elements of the site.

---

# 6. GLOBAL NAVIGATION

Desktop navbar:

```text
AMAN                 WORK   LAB   ABOUT   RESUME   ● MITRA
```

The navbar should be:

* Sticky
* Minimal
* Floating or subtly separated from the page
* Slightly translucent after scrolling
* Backdrop blurred
* Thin border
* Rounded corners if appropriate

On initial page load it may appear more transparent.

After scrolling:

* Background becomes slightly more opaque
* Blur increases
* Subtle border appears

Do not make the navbar visually dominant.

# 16. PROJECT MICRO-INTERACTIONS

# 34. MICRO-INTERACTION SYSTEM

Create one consistent interaction language.

## Buttons

Hover:

* Slight translate
* Arrow movement
* Background transition

## Cards

Hover:

* 2–4px movement
* Slight border change
* Slight shadow

## Links

External links show:

```text
↗
```

Arrow moves slightly on hover.

## Numbers

Animate into view when appropriate.

## Section titles

Fade/translate into view.

## Images

Subtle scale on hover.

## Navbar

Blur/transparency changes after scroll.

## Command palette

Scale + fade + background blur.

## Live status

Small popover animation.

## Email

Copy confirmation.

---

# 35. MAGNETIC BUTTONS

Implement only on desktop.

Primary CTA buttons can have a very subtle magnetic effect.

Maximum movement:

**3–5px**

Never allow the button to dramatically follow the cursor.

Disable on touch devices.

---

# 36. CURSOR

Do not use a large custom cursor.

Default cursor should remain normal.

If implemented, use only an extremely subtle accent interaction.

The portfolio must remain professional without cursor effects.

---

# 37. SCROLL EXPERIENCE

Implement:

* Smooth scrolling
* Thin scroll progress indicator
* Section reveal animations
* Subtle project transitions

Avoid excessive parallax.

Scroll should feel responsive and fast.

---

# 38. ANIMATION PRINCIPLES

All animation must answer at least one of:

1. Provide feedback
2. Establish hierarchy
3. Explain navigation
4. Create continuity
5. Improve delight

Do not animate something simply because it can be animated.

Use fast, smooth easing.

Avoid long delays.

---

# 39. REDUCED MOTION

Respect:

```text
prefers-reduced-motion
```

When enabled:

* Disable unnecessary animations
* Disable magnetic effects
* Disable parallax
* Remove animated number transitions
* Keep all functionality intact

---

# 40. RESPONSIVE DESIGN

Desktop, tablet and mobile must all be designed intentionally.

Desktop:

* Large typography
* Multi-column layouts
* Large project visuals
* Command palette

Tablet:

* Reduced grid
* Smaller typography
* Maintain visual hierarchy

Mobile:

* Single-column layouts
* Compact navbar
* Touch-friendly controls
* No magnetic interactions
* No unnecessary cursor effects
* Command palette becomes a mobile sheet/modal
* GitHub graph should remain usable

Never simply shrink desktop CSS.

---

# 41. ACCESSIBILITY

Requirements:

* Semantic HTML
* Keyboard navigation
* Visible focus states
* Proper heading hierarchy
* Alt text
* Accessible buttons
* Accessible dialogs
* Accessible command palette
* Color contrast
* Reduced-motion support
* Screen-reader labels for icon-only controls

---

# 42. PERFORMANCE

Performance is a core requirement.

Prioritize:

* Fast initial load
* Optimized images
* Lazy loading
* Code splitting
* Minimal client-side JavaScript
* Avoid unnecessary dependencies
* Avoid heavy 3D scenes
* Avoid loading external APIs on the critical path
* Use server-side fetching where appropriate
* Cache public API data where possible

Target:

**Excellent Lighthouse performance on desktop and mobile.**

Do not sacrifice performance for visual effects.

---

* Structured metadata where useful

# 50. DESIGN QUALITY BAR

Before considering the project complete, inspect:

### Visual

* Does it look premium?
* Is spacing consistent?
* Are typography scales coherent?
* Are sections visually related?
* Is the accent color restrained?

### UX

* Can a recruiter find the resume immediately?
* Can someone understand the projects quickly?
* Is navigation obvious?
* Does the command palette work?
* Are external profiles easy to access?

### Engineering

* Is the code modular?
* Are dynamic APIs isolated?
* Are errors handled?
* Is mobile responsive?
* Is accessibility implemented?

### Performance

* Is the first load fast?
* Are images optimized?
* Are animations lightweight?
* Is unnecessary JavaScript avoided?

# 53. IMPORTANT IMPLEMENTATION RULE

Do not blindly implement every idea in this document.

The priority hierarchy is:

```text
1. Content clarity
2. Professional appearance
3. Performance
4. Accessibility
5. Navigation
6. Micro-interactions
7. Visual experimentation
```

If an animation conflicts with readability or performance, remove the animation.

If a visual effect conflicts with professionalism, remove the effect.

The final site should feel **effortless**, not overloaded.

* The homepage is visually polished
* All major sections are responsive
* Projects have dedicated case studies
